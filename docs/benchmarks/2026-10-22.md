The README's selection table comes from successful paired consumer runs recorded
in [pytest-selective's benchmark](https://github.com/gigaverse-app/pytest-selective/blob/1432cd14112169c7dbdaf2c1f42c507b96807621/docs/benchmarks/2026-10-22.md).
Each comparison uses one PR head and one checked-out merge commit, first selected
and then with `test:full`. Both include planner overhead. These measure routing,
not CI-esta completion-receipt reuse. The Due main-CI row excludes its separate
widget workflow, whose control had a 624-second browser-install outlier.

The later [routing audit](https://github.com/gigaverse-app/pytest-selective/blob/main/docs/benchmarks/2026-10-22-routing.md)

(92.3% reduction), and 211s to 26s elapsed. It preserves routing, Markdown,
distribution metadata and installed-wheel checks. The raw timestamps and tested
merge identity are linked there. Its Due docs-only run (26s elapsed, 91 summed
runner-seconds) is a preservation observation without a paired full control.

The report's 18 rounded runner minutes are a per-job ceiling estimate, not a
billing record. No dollar figure is claimed. The observer ran after validation;
separating it removes a workflow dependency, but does not eliminate its compute
cost. This single run is not a before/after benchmark of reporter placement.

The data identifies Windows test execution as the next place to investigate.
It does not justify removing Windows coverage from code changes. Documentation
can skip unrelated test matrices while retaining Markdown, package metadata,
installed-wheel checks and routing regressions.

## Reproduce the rendering

With the repository's locked environment:

```bash
uv run ci-esta render docs/benchmarks/2026-10-22-selective-report.json \
  --markdown /tmp/selective-report.md --prometheus /tmp/selective-report.prom
```

The saved JSON allows offline inspection after the hosted artifact expires.
For a new collection, `ci-esta report` uses an ordinary read token in
`GH_TOKEN` or `GITHUB_TOKEN`; never put it in a command argument or a report.

## Adoption boundaries

- Use the completed-run observer for timing and overlapping-run evidence. It
  must not become a prerequisite of the validation jobs it measures.
- Use pytest-selective for affected-input routing. Explicit non-Python inputs,
  missing-history fallbacks and full checkpoints remain necessary.
- Due uses CI-esta's strict aggregate gate to preserve required check names when
  a successful plan authorizes a skip. This is not conformance receipt reuse.
- Before reusing expensive recovery/conformance lanes, account for external
  services, tool versions, environment and configuration inputs. Keep validators
  coupled to the tests producing their evidence. No conformance-reuse speedup is
  measured in this report.
